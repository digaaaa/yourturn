YourTurn helps roommates decide whose turn it is to complete chores and buy shared supplies. Assignment 2 preserves the original turn rules, reminders, and monthly totals while changing how the system is deployed and how its data is owned.

Assignment 2 · two independently runnable APIs

Browser ← static HTML, CSS, JS ← nginx locally / Storage on Azure
   ├─ JSON → Chores API   → Chores SQL database
   └─ JSON → Supplies API → Supplies SQL database

Supplies → GET /roommates → Chores
Chores   → GET /supplies/spending → Supplies

The seam from ADR 2 held. Chores owns the roster. Supplies receives roommate IDs and names over HTTP and stores only their IDs in purchase records. The reciprocal spending request returns totals by ID. This avoids shared credentials, cross-database joins, and duplicate roommate tables.

The static UI calls both APIs directly, uses their configured origins, and replaces the original server-rendered forms with JSON requests. The original Flask monolith and SQLite files remain available for comparison and regression tests.

/health checks the service's own database by reading a row and verifying a write inside a transaction that is rolled back. It returns 503 on database failure and embeds the build SHA in CI and deployed images. Startup retries give SQL time to resume after a cold start.

Decisions, evidence, and release status

Why these choices fit the project

  • HTTP rather than a shared database. Ownership is visible and testable. The peer can fail independently, so optional views degrade and writes that require the roster return a clear error.
  • Numbered SQL rather than an ORM migration tool. Both services already use SQL directly. On a bad migration, preserve the existing database, use a corrective migration, and restore to a separately reviewed database only if recovery demands it.
  • Consumption and a static website. There are two app processes. Static files need no application process, and idle apps can scale to zero. Startup latency is the trade-off.
  • One pipeline with an explicit gate. The code that passes CI is the code tagged in GHCR. Deployment uses the same SHA and waits for that exact version to respond.
