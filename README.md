# YourTurn

YourTurn answers the question every shared flat argues about: **"whose turn is it?"** Roommates pick their name (no login) and the app keeps track of two things:

- **Chores**: chores repeat on a schedule (e.g. dishes daily, bathroom weekly). When someone presses "I did it", the app logs it and shows whose turn is next. It also flags overdue chores ("bins not done for 3 days") and shows who did the most chores this month.
- **Shared supplies**: shared items like eggs, coffee pods or toilet paper. When someone presses "I bought it" and enters the price, the app shows whose turn it is to buy next and how much each roommate has spent this month.

## Assignment 2 local stack

The browser loads static files from nginx and calls two Flask APIs. Each API has its own Dockerfile, database, and SQL login. Chores owns the roommate roster, chore schedules and completion history. Supplies owns supply inventory and purchase history. Supplies asks Chores for roommate IDs and names. Chores asks Supplies for the optional spending summary. A missing peer leaves the other domain available.

| Component | Local address | Data owned |
| --- | --- | --- |
| Static UI | http://localhost:8080 | Static files in `ui/` |
| Chores | http://localhost:8001 | `roommates`, `chores`, `chore_log` |
| Supplies | http://localhost:8002 | `supplies`, `purchases` |
| SQL Server | TCP 1433 | `yourturn_chores` and `yourturn_supplies` in `sqlserver_data` |

### Start from a clean clone

Install Docker Desktop with Compose V2. On Apple Silicon, enable Rosetta emulation for the SQL Server image. From the repository root, set three unique passwords in a local, ignored `.env`. Keep the same passwords when restarting an existing volume. Generate them in PowerShell with the following one-time command.

```powershell
if (Test-Path -LiteralPath .env) { throw 'Keep the existing .env' }
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
try {
    foreach ($name in 'MSSQL_SA_PASSWORD','CHORES_DB_PASSWORD','SUPPLIES_DB_PASSWORD') {
        $bytes = New-Object byte[] 24
        $rng.GetBytes($bytes)
        $value = 'Aa1_' + [BitConverter]::ToString($bytes).Replace('-', '')
        Add-Content -LiteralPath .env -Value "$name=$value" -Encoding ascii
    }
} finally { $rng.Dispose() }
docker compose up --build
```

In Bash, use the same three variable names with independent values generated by `openssl rand -hex 24`, prefix each value with `Aa1_`, and write them to `.env` without echoing them. The two service passwords accept 16–64 ASCII letters, digits or underscores. Then run `docker compose up --build` and open the static UI.

For Chores only, run `docker compose up --build chores`. For Supplies only, use `docker compose up --build supplies`. Both commands start the database dependencies. Supplies can show its inventory by itself. Start Chores as well to log a purchase.

| Variable | Default or source |

### Database migrations and legacy data

`db-init` creates the databases and logins idempotently. Each service then runs its own numbered SQL files in order and records each successful file in its own `schema_migrations` table. Edit a schema through a new numbered file. Chores migration 003 adds a UTC insertion timestamp for new completions. Existing completion dates and history survive. Restarting containers retains the named volume.

To transfer a legacy database, keep a backup of the SQLite file and start the target services on SQL Server. Run `scripts/import_legacy.py` for `chores` first, then `supplies`, using the same SQLite file and each domain's respective `DATABASE_URL`. Supply `CHORES_SERVICE_URL` for the Supplies import so it can map legacy roommates to the canonical roster. The importer opens SQLite read-only and rolls back conflicting target IDs. Configure the destination through the environment and keep write traffic paused while importing.

```bash
python scripts/import_legacy.py chores /path/to/yourturn.db
python scripts/import_legacy.py supplies /path/to/yourturn.db
python scripts/migration_snapshot.py
```

The snapshot command uses the Chores database URL. It prints schema, migration history, row count, and a fingerprint of the original fields without printing the underlying records.

The [Azure baseline](report/evidence/azure-baseline.json) had one chore completion. The [after-migration evidence](report/evidence/azure-after-migration.json) shows the same row fingerprint and demonstrates that a new completion receives a UTC insertion timestamp. [GitHub Actions deployed migration 003](https://github.com/digaaaa/yourturn/actions/runs/44935452608).

### Troubleshooting and limitations

- Check `docker compose ps -a` and `docker compose logs db-init chores supplies` if startup fails. Verify that the three local password settings belong to the current volume. Keep existing volumes when troubleshooting.
- If the browser shows a CORS error, open the UI using its configured origin, including the correct hostname and port.
- Each `/health` checks the service's own database and rolls its probe write back. An unavailable peer affects the cross-service action, while local routes can still work. Requests log their method, path, status, and elapsed time to stdout.
- The app retains Assignment 1's roommate picker. It currently has no sign-in or protection against a direct public API caller submitting a write.

## Architecture

```
                    app.py  (Flask app, registers both blueprints)
                 /                                        \
     chores/  (Domain 1: time)                 supplies/  (Domain 2: money)
       routes.py      Flask Blueprint /chores    routes.py      Flask Blueprint /supplies
       service.py     logic                      service.py     logic
       rules.py       TakeTurns, LeastRecent     rules.py       TakeTurns, LeastSpent
       repository.py  SQL only                   repository.py  SQL only
            |                                         |
     chores, chore_log  ---->  roommates  <----  supplies, purchases
                          (the only shared table = the seam)
```

Each domain owns its own rules, logic, SQL and pages. They share **only** the `roommates` table, so in Assignment 2 they can be split into two services along that seam. The reasons are in [ADR.md](ADR.md).

- **Strategy pattern**: each "who's next" rule (`TakeTurns`, `LeastRecent`, `LeastSpent`) is a class with a `next_person(...)` method, so a chore or supply can use any rule.
- **`factory_map`**: the rule name stored in the database (e.g. `"least_spent"`) is turned into the right rule object by a small dictionary.
- **Service receives its repository**: the logic never writes SQL itself, which keeps it easy to test.

## Run it locally

Requires Python 3.10 or newer.

```bash
git clone https://github.com/digaaaa/yourturn.git
cd yourturn
python -m venv .venv
```

Activate the virtual environment:

```bash
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
```

Install and start:

```bash
pip install -r requirements.txt
python app.py
```

Then open http://localhost:8000. There is no setup step: on first start the app creates the database tables and loads the demo data from `seed.json` by itself.

## Configuration

Everything is configured with environment variables. None are required and no `.env` file is needed.

| Variable | Default | What it does |
|---|---|---|
| `PORT` | `8000` | Port the web server listens on. The server always binds to `0.0.0.0`. |
| `DATA_DIR` | `./data` | Folder where the SQLite database is stored. Created automatically if missing. |

**SQLite path:** `<DATA_DIR>/yourturn.db`, so `./data/yourturn.db` by default (for example `/data/yourturn.db` when `DATA_DIR=/data`).

Example with custom settings:

```bash
# Windows PowerShell
$env:PORT="9000"; $env:DATA_DIR="C:\temp\yourturn"; python app.py
# macOS / Linux
PORT=9000 DATA_DIR=/tmp/yourturn python app.py
```

**Startup behaviour:**
- Tables are created with `CREATE TABLE IF NOT EXISTS`, so restarting never deletes data.
- `seed.json` is only loaded into tables that are still empty, so starting the app twice never duplicates rows.
